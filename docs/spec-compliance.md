# 设计规范对照与技术说明

对照文件：小米《HyperOS 小部件设计规范》《小部件审核规范》（dev.mi.com，2025-03 版）。

## 1. 尺寸与网格

| 项目 | 规范值 | 本实现 |
| --- | --- | --- |
| 手机支持的组件尺寸 | 1×1、2×2、4×2、4×4 | 1×1、2×2、4×2 |
| 设计稿基准 | 1080×2340，格子约 70×80dp | 1×1 = 110×110dp，2×2 = 220×220dp，4×2 = 474×220dp（与 1080p 下 220/440/948px 对应） |
| Android 声明 | — | 1×1：`minWidth/minHeight=40dp`；2×2：`110dp`；4×2：`250dp×110dp`；均带 `targetCellWidth/Height` |
| 自适应 | 4×6、5×7 布局、有无搜索框、有无虚拟键、1080p/2K | 内容全部用 `wrap_content` + 底部对齐 + 单行省略，横向拉伸只增加留白，不改变文字尺寸 |

> `minWidth/minHeight` 只决定占几格，实际显示尺寸由桌面网格决定，因此布局里没有写死高度，只在必要时用 `layout_gravity="bottom"` 固定阅读锚点。

## 2. 圆角与安全区

| 屏幕 | 规范圆角 | 规范安全区 | 换算 | 实现 |
| --- | --- | --- | --- | --- |
| 1080p（≈360dp 宽） | 55px | ≥42px | 55/3≈18.3dp，42/3=14dp | `widget_corner=18dp`，`widget_padding=16dp` |
| 2K（≈411dp 宽） | 73px | ≥55px | 73/3.5≈20.9dp，55/3.5≈15.7dp | `values-sw411dp`：`21dp` / `18dp` |

1×1 的格子只有 60–90dp，安全区等比收一档到 `12dp`（`sw411dp` 下 `14dp`）；
2×2 现在只有人像、没有文字，边距与 4×2 对齐，同样是 `16dp`（`sw411dp` 下 `18dp`），
人像在安全区内等比撑满，不会被圆角切到。

预览图按规范**交付直角**，由系统统一裁 55px 平滑圆角；资源里不带圆角，避免二次裁剪出现「圆角外套圆角」。

## 3. 文字

| 层级 | 规范 | 本实现 |
| --- | --- | --- |
| 字体 | 推荐 MiSans | `sans-serif-medium` / `sans-serif`：小米设备系统默认字体即 MiSans，三方设备自动回退系统无衬线体 |
| 主信息字重 | Demibold / Medium | 组件标题 26sp `sans-serif-medium`，字距 0.04em |
| 次要信息 | Medium + 40% 透明度 | 副标题 11sp，颜色 `#661A1C1A`（浅色）/ `#66F1F4F1`（深色），恰好 40% |
| 字色层级 | 主/次/辅三级 | `text_primary`、`text_secondary(40%)`，辅助信息用透明度再降一档（图标与底色） |

## 4. 颜色

| Token | 浅色 | 深色 | 用途 |
| --- | --- | --- | --- |
| `widget_bg` | `#FFFFFF` | `#1A2130` | 组件卡片底（4×2） |
| `hero_top` / `hero_bottom` | `#F3F9FF` / `#C3DCF6` | `#26333F` / `#151E28` | 2×2 渐变底（上浅下深） |
| `hero_glow` | `#99FFFFFF` | `#1FFFFFFF` | 2×2 头部后方的柔光，`gradientRadius=74dp` |
| `tile_bg` | `#F1F8FF` | `#1A2431` | 1×1 格子底 |
| `text_primary` | `#1A1C1A` | `#F1F4F1` | 标题 |
| `text_secondary` | `#661A1C1A` | `#66F1F4F1` | 副标题（40%） |
| `accent` | `#3C82D6` | `#8FC2F5` | 时钟图标、按钮（取自插画里的衣袍蓝） |
| `widget_chip_bg` | `#0D1A1C1A` | `#14FFFFFF` | 4×2 内部热区底 |

深色模式不是简单反色：卡片改为带一点冷调的近黑（`#1A2130`），与澎湃 OS 深色桌面的中性色一致；
2×2 的渐变改成「夜色蓝」而不是把浅色渐变直接反相；强调色提亮到 `#8FC2F5` 保证在深底上的对比度。

组件里的主图案是位图（从插画抠出的打坐人像，`mark_figure.png`），不是矢量：
插画本身带肤色与衣褶的柔和过渡，256 色「RGB 中位切分 + 原始 alpha」后 512 见方约 71KB，
比手写贝塞尔曲线更接近原图，也不会在 120dp 的显示尺寸下露馅。
唯一例外是「屏幕用时」的时钟——保持矢量，任何密度都锐利。

## 5. 交互与无障碍

- 1×1 整格一个点击区；2×2 整块卡片一个点击区；4×2 两个互不重叠的热区（左 = 剩余宽度，右 = 104dp，间隔 8dp，均大于 48dp 最小可点尺寸）。
- 每个热区一个 `contentDescription`，TalkBack 按「打开系统专注模式 / 打开屏幕使用时间」整块播报，符合「仅信息展示 + 操作按钮 → 按焦点播报」的建议。
- 1×1 与 2×2 都不放文字：1×1 一格宽只有 60–90dp，文字只能压到 11sp 以下；2×2 去掉文字后人像能多占 40dp 高度，整块更像海报。图形（人像/时钟）承担识别，无障碍信息由 `contentDescription` 提供。
- 剩余文字全部 `maxLines=1` + `ellipsize=end`，系统字体放大到 1.3× 时不会撑破卡片。
- 无滑动容器、无输入框，符合「禁止能力」两条。
- 点击无「静默失败」：候选 Activity 在 `onUpdate` 阶段就做 `exported` 校验，失败则 PendingIntent 指向引导页。

## 6. 命名与文案

| 项 | 规范 | 本实现 |
| --- | --- | --- |
| 组件名 | 2~10 汉字，格式「应用名·组件名」，且不得与应用名相同 | 应用「静叶」；组件「专注小格」（4 字）、「屏幕用时」（4 字）、「专注入口」（4 字）、「专注与屏幕时间」（7 字） |
| 组件介绍 | ≤22 字符 | 「点一下，直达系统专注模式」（12 字）等，均 ≤20 字 |
| 禁止 | 不得含小米元素、极限词、商业化用语 | 文案中无「小米」「最」「第一」等 |

## 7. 图标与控制中心磁贴

| 项 | 说明 |
| --- | --- |
| 桌面图标 | 自适应图标：渐变底（`#F3F9FF→#C3DCF6`）+ 前景；前景与单色层都是 `mark_figure` / `ic_mono` 的 `<inset 20%>` 版本，内容正好落在 66dp 安全区内，一套图两处用，少两张 432 的图 |
| 磁贴图标 | 24dp 单色剪影，按 5 档密度出图（24/36/48/72/96px），浅色界面深墨 `#464E5A`、深色界面纯白 |
| 为什么这么做 | 磁贴图标原本是矢量 `<path>` 但漏了 `fillColor`，渲染为空 → 只有文字没有图标。改成位图后同时规避了「系统不给你着色」的 ROM 差异 |

## 8. 与审核流程的差距（重要）

规范里的小部件中心是**开发者提审制**：需要在 dev.mi.com 提交包名、设计稿、预览图，由小米审核后才会进入「小部件中心」精选池。个人自用安装 APK 时，组件只会出现在桌面编辑页的「安卓小部件」分类里——功能完全正常，只是没有精选位的曝光。

如果要走正式上架：

1. 把 `applicationId` 改成自己的域名倒写，用正式签名打包；
2. 准备 1×1 / 2×2 / 4×2 / 4×4 四档设计稿与浅深两套预览图；
3. 邮件至 `miui-widget@xiaomi.com` 申请适配沟通，按回复提交审核。

## 9. 为什么不直接「开始 25 分钟专注」

`FocusSettingsMainActivity` 只接受空 Intent，系统没有公开带时长/预设启动的 extra（不同版本签名校验也不同）。硬塞 extra 在部分版本会直接抛异常或忽略，反而制造「点了没反应」的体验，因此组件只做「一步到页面」，时长在系统页面里选——这已经比原来的 4 步路径省掉 3 步。

如果后续某个版本公开了入口参数，只需在 `FocusLauncher.candidates()` 前面插一条带 extra 的 Intent 即可，其余逻辑不动。
